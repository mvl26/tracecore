# TraceCore role administration implementation plan

Goal: deliver the approved role-based Vue administration shell on a separate branch, with real permission-filtered data, without merging.

Architecture: Vue 3 + TypeScript + Vite served at /tracecore, Frappe cookie session and CSRF. Backend returns available roles, explicitly supported screens, lists and details. One screen registry defines permissions and safe fields. Existing station workflows remain separate until migrated; no simulated approvals or invented production data.

Design: docs/tracecore-admin-design.md and docs/tracecore-ui-source-review.md; role prototype approved 2026-10-25. Preserve source role taxonomy and design tokens. Administrator sees all role spaces; ordinary accounts see their explicitly assigned TC roles. Broader access requires explicit TC Admin Overview role; this never bypasses record permissions. Desk bypass is Administrator or explicitly assigned TraceCore Desk Access only, rollout guarded by site flag.

- [ ] Backend tests first: anonymous denied, explicit role isolation, record permissions, allowed screen/field registry, pagination/search bounds, unknown screen denied, server-side Desk guard exceptions. File: tracecore/tests/test_admin_ui.py. Run on bench test_site, demonstrate failure before implementation.
- [ ] Backend registry/read API: tracecore/ui/admin_registry.py, tracecore/v1/admin_ui.py. Bootstrap returns user, role spaces and capability for screens. Lists use get_list, details use document permission and safe metadata-selected fields; no ignore_permissions. Unsupported features are marked unavailable. Dashboard uses only permission-filtered sources. No patient codes or credential fields.
- [ ] SPA entry, Frappe route and guard: tracecore/www/tracecore.html, tracecore/www/tracecore.py, tracecore/ui/admin_access.py and hooks.py. Guest HTML includes CSRF for login; fetch bootstrap after complete Frappe authentication. Preserve stock password and OTP login handling. No cache of session HTML. Backend /app guard behind rollout; preserve station/launcher exceptions, never redirect API/assets.
- [ ] Frontend: frontend/package.json, lockfile, vite.config.ts, tsconfig.json, src/api.ts, src/main.ts, src/router.ts, src/App.vue, src/style.css. White sidebar by role, overview cards, real dashboard/list/detail, search/pagination, loading/empty/errors/offline, unavailable state. Vue escapes all record content. Login/logout/OTP session state. Routes are internal and reject unauthorized role/screen.
- [ ] Functional M1 first slice: native Vue list/detail and permitted form actions for Instrument, Instrument Set Type and Set Unit, using existing business RPC for specialized operations. Do not write lifecycle state generically. If workflow not yet ported, explicitly report limitation; never link operational users back to Desk.
- [ ] Verification: build + vue-tsc, frontend tests for routing/session/error behavior; bench API tests plus existing launcher/account tests. Smoke /tracecore and deep links with real session, unauthorized requests, assets and station exceptions. Inspect browser and correct failures.
- [ ] Docs: update README local/build/rollout and A-35, preserve prototype in docs reference. Commit only scoped files, push codex/tracecore-role-admin-ui. Never merge. Report exact verification and outstanding features.
